## 3. Үлдсэн ажил (дарааллаар)

### 3.1 Түймрийн суурь давтамжийг дахин тохируулах (Earth Engine шаардана)

**Асуудал.** `pipeline/model.json` → `fire.base = 0.0001784` нь 2001–2025 оны дундаж (нэг 0.1° нүд, нэг өдөрт MODIS гал илрэх магадлал). Гэвч гал цөөрсөн: 2001–2017 онд жилд ≈1,580 нүд-өдөр, 2018–2025 онд ≈410 (`verification.n = 3284` / 8 жил). 2018–2025 оны ажиглагдсан давтамж = 3284 / (18,467 нүд × 2,922 өдөр) = 0.0000609, өөрөөр хэлбэл суурийн 1/2.93. Загварын `u_model = 15.8` оноо нь бараг бүхэлдээ энэ нэг чиглэлтэй хазайлт (20·log₄(2.93) = 15.5), санамсаргүй алдаа биш.

**Одоо сайт дээр юу хийсэн (түр шийдэл, тооцоо дахин ажиллуулалгүй).** Үг хэллэгийг засаж, зөрүүг ил бичсэн (доорх 4-р хэсгийг үз). Оноо өөрөө өөрчлөгдөөгүй.

**Жинхэнэ засвар.** `pipeline/calibrate.py`-д цаг хугацааны өөрчлөлтийг оруулна. Хоёр сонголт:
1. *Энгийн:* `fire()` дотор үйлдвэрлэлийн загварыг бүх оноор биш, сүүлийн 10–12 жилээр (жишээ нь 2014–2025) тохируулах, `base`-ийг мөн тэр хугацаагаар авах. Сул тал: сургалтын гал цөөрнө.
2. *Илүү зөв:* `fire_design`-д оны шугаман гишүүн (жишээ нь `(year − 2013) / 10`) нэмж, шалгалтын онуудад найдвартай байдлын зөрүү (`verify()` доторх `gaps`) 0 орчим болсныг шалгах. Ирээдүй рүү экстраполяц хийхгүйн тулд гишүүнийг сүүлийн сургалтын оны утгаар хязгаарлана.

Алхам:
```bash
# 26 жилийн кэш хэрэгтэй (≈ хэдэн GB). Байршил: HAZARD_CACHE орчны хувьсагч, эсвэл репогийн хажуугийн ../gee_cache
# Кэш байхгүй бол pipeline/fetch_era5.py, fetch_obs.py, fetch_static.py-г Earth Engine нэвтрэлттэй ажиллуулж татна (docs/GEE_SETUP.md, docs/GEE_DATA_FORMAT.md).
pip install -r pipeline/requirements.txt
earthengine authenticate            # төсөл: sigma-513109 (EE_PROJECT)
cd pipeline
python calibrate.py prep            # FWI, сарын бороо
python calibrate.py fire            # model.json-д fire.beta, base, verification, u_model бичнэ
python calibrate.py uinput          # оролтын алдааны хүснэгт
python build.py                     # data/gee-г бүх оноор дахин бичнэ (урт)
```
Шалгах: `model.json` → `fire.u_model` 15.8-аас мэдэгдэхүйц буурсан (≈5–8), `auc` 0.90 орчим хэвээр. Дараа нь `js/meaning.js` → `SCORE_MODEL.fire.base`, `seen` утгыг `model.json`-оос шинэчилж, `tests/meaning.test.mjs` тэнцэхийг үз. `js/methods.js` → fire.limits-ийн «≈400, өмнө нь ≈1700» мөрийг шинэ тоогоор соль.

### 3.2 Түймрийн «SPI»-г жинхэнэ SPI болгох (Earth Engine шаардана)

**Асуудал.** `pipeline/calibrate.py` → `monthly_spi()` нь сарын борооны `(r − дундаж) / стандарт хазайлт`-ыг тооцдог. Энэ нь SPI биш: SPI нь сар бүрийн бороонд гамма тархалт тааруулж, хэвийн тархалтын квантиль руу хөрвүүлдэг (McKee нар 1993; WMO-No. 1090). Монголын хуурай саруудад бороо хазгай тархалттай тул энгийн z-оноо −1.5-аас доош бараг гардаггүй, өөрөөр хэлбэл `spi_class()`-ийн 5-р анги (хүчтэй ган) хүрэх боломжгүй болдог. Жин нь бага (2/21) тул онооны нөлөө бага ч нэр нь буруу.

**Одоо хийсэн.** Арга зүйн цонхонд «SPI» биш «борооны стандартчилсан хазайлт» гэж нэрлэсэн.

**Жинхэнэ засвар.** `monthly_spi()`-д сар, нүд бүрээр гамма тааруулалт (тэг бороотой сарын хувийг тусад нь тооцно: H(x) = q + (1 − q)·G(x)), `scipy.stats.gamma.fit(..., floc=0)` ба `norm.ppf`. `model_fire.npz`-д `spi_mu`, `spi_sd`-ийн оронд гаммагийн параметр (`shape`, `scale`, `q`) хадгалж, `pipeline/scores.py` → `fire_S_month()`-ийг мөн адил өөрчилнө. Дараа нь 3.1-ийн алхмаар дахин тохируулна. `pipeline/requirements.txt`-д `scipy` нэмнэ.

### 3.5 Шороон шуурганы нарийвчлалыг өсгөх (хамгийн их үр өгөөжтэйгээс нь)

Одоогийн улсын тоосны загвар (`pipeline/calibrate.py` → `dust()`): AUC 0.69, «өндөр» гэсэн 1000 нүд-өдрийн ≈100-д нь л үзэгдэл, ажиглагдсан үзэгдлийн 13%-ийг л барьдаг. Шалтгаан нь голчлон **лавлах ажиглалт** (TROPOMI: өдөрт нэг удаа, үүлэн дор харахгүй, утааг тоосноос ялгахгүй) ба **зөвхөн 3–5 сараар** тохируулсанд байгаа. Дараах алхмуудыг энэ дарааллаар хий; бүгд Earth Engine-ийн кэш, эсвэл гадаад өгөгдөл шаардана.

1. **Станцын SYNOP ажиглалтыг лавлагаа болгох.** NOAA-гийн Integrated Surface Database (нээлттэй): `https://www.ncei.noaa.gov/data/global-hourly/access/<он>/<USAF><WBAN>.csv`, Монголын станцууд (USAF 442xx–443xx). Одоогийн цаг агаарын код (WMO 4677 хүснэгт): 06–09 ба 30–35 нь тоос, шороон шуурга (кодын утгыг WMO-No. 306-аас өөрөөс нь шалга). Станц бүрийг 0.1° нүдтэй холбож «тоостой нүд-өдөр» гаргана. Хэрэглээ: (а) одоогийн оноог станцын нүднүүд дээр шалгах (POD, FAR, AUC, найдвартай байдлын муруй); (б) логистик регрессийг TROPOMI-ийн оронд эсвэл хамт SYNOP-оор тохируулах. Энэ нь `js/methods.js`-ийн тоосны хязгаарлалтад «хамгийн зөв лавлагаа, одоохондоо ашиглаагүй» гэж бичсэн зүйл.
2. **Бүх улирлаар тохируулах.** `DUST_MONTHS = (3, 4, 5)`-ийг бүх сар болгож, `dust_design`-д сарын гишүүн (sin, cos) эсвэл улирлын тогтмол нэм. Одоо 3–5 сараас бусад үед цонх «найдвар багатай» гэж анхааруулдаг (`off_season_dust`); тохируулсны дараа `js/meaning.js` → `SCORE_MODEL.dust.months`-ийг шинэчил.
3. **Нүд бүрийн босго салхи.** `dust_design`-ийн тогтмол 6 м/с хугарлын оронд газрын бүрхэвчээс хамаарсан босго (Kurosaki, Mikami 2007: говь 8.9/13.8, хээр 9.8/16.2 м/с), эсвэл 1-р алхмын SYNOP-оос тэдний аргаар (салхины ангилал бүрд тоосны давтамж 5%, 50% хүрэх хурд) нүд бүрд тооц. Хуудсан дээрх нарийвчилсан шалгалт үүнийг аль хэдийн хийдэг (`windLimits` in `js/aoi/dust.js`).
4. **Хуй салхи (gust).** ERA5-Land-ын 3 цагийн дундаж салхины оронд ERA5-ын `instantaneous_10m_wind_gust` (цаг тутам, 0.25°)-ыг нэмэлт хувьсагчаар оруул: тоосыг дундаж биш, оргил салхи өргөдөг. `pipeline/fetch_era5.py`-д зурвас нэмнэ.
5. **Хөлдүү хөрс.** Хөрсний 1-р давхаргын температур 0 °C-аас доош үед ялгаралтыг дарах гишүүн нэм (арга зүйн цонхонд Wu нарын аргын 3-р сарын сул талыг «хөлдүү хөрс, цас» гэж тэмдэглэсэн).
6. **Геостационар хиймэл дагуул (Himawari-8/9 AHI).** 10 минут тутам, шөнө ч хардаг. Нийтлэгдсэн аргууд: дулааны сувгуудын зөрүүний харьцаа (D*-параметр, Shin нар 2021, Asia-Pac. J. Atmos. Sci. 57), олон сувгийн ба олон цагийн нэгдсэн индекс (Shi нар 2023, Earth and Space Science 10, e2022EA002738: TROPOMI-той 90%-иас дээш таарсан, 2021-03-14–16-ны шуургыг шөнөөр нь дагасан; манай туршилтад TROPOMI яг тэр шуургыг үүлэн дор алдсан). Хэрэглээ: өдрийн зургийн «ажиглагдсан тоос» нэмэлт (`OBSERVED_DUST_SCORE` in `pipeline/scores.py`) ба хоёр дахь лавлагаа. Шалгах зүйл: Монголын баруун хэсэг Himawari-ийн дискний захад ордог тул харах өнцгийн хязгаар; өгөгдлийн эх (JAXA P-Tree, AWS нээлттэй өгөгдөл) Earth Engine-д байхгүй байж магадгүй.
7. **Шалгалтын стандарт.** Он тусгаарласан шалгалт дээр орон зайн блокоор тусгаарлалт нэм; Брайерын ур чадварын оноо (уур амьсгалын дундажтай харьцуулсан), найдвартай байдлын муруйг бүс (говь, хээр, ойт хээр) ба улирал тус бүрээр гарга. `verify()`-ийн `gaps`-ийг `model.json`-д хадгал: одоо зөвхөн `u_model` (RMS) хадгалагддаг тул хазайлт уу, тархалт уу гэдэг нь харагдахгүй.
8. **Хуудсан дээрх шалгалтыг баталгаажуулах.** `windLimits`-ийн босго нь нийтлэлээс авсан, орон нутагт тааруулаагүй. 1-р алхмын SYNOP-оос дор хаяж 30 шуургатай, 30 тайван өдөр сонгож, `docs/METHODS.md`-ийн 6 өдрийн хүснэгтийг өргөтгө; босгыг F1-ээр тохируул.

### 3.4 Жижиг ажлууд (Earth Engine шаардахгүй)

## 4. Энэ салбарт нэмэлтээр хийгдсэн зүйлс

- **Түймрийн суурь давтамж (3.1-ийн түр шийдэл):** `js/meaning.js` → `SCORE_MODEL.fire.seen`, `drift()`. Цонх «улсын ердийн өдрийнхөөс X дахин» гэж хэлж, «Загварын нарийвчлал» хэсэгт 2018–2025 онд гал 2.9 дахин цөөн байсныг нэг чиглэлтэй зөрүү гэж бичнэ (`v_drift`).

- **Тоосны нарийвчилсан шалгалт (`js/aoi/dust.js`):** «нөхцөл бүрдсэн», «шуургатай» гэсэн босго одоо Sentinel-2-оор хэмжсэн ил хөрсний хувиар говь (8.9, 13.8 м/с) ба хээрийн (9.8, 16.2 м/с) нийтлэгдсэн босгын хооронд авагдана (`windLimits`); гадаргын зураггүй бол хуучин 10, 14 м/с. Өнгөн хөрсний чийг 0.25 м³/м³-ээс их цагийг тоолохгүй. Баримтжуулсан 6 өдрийн дүгнэлт өөрчлөгдөөгүйг тест барина. Орон нутгийн өгөгдлөөр баталгаажаагүй (3.5-ын 8).
